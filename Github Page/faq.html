FAQ & Troubleshooting

Quick answers to the questions that come up most often, and fixes for the issues you're most likely to hit during install and first run.

General

Is CRANE production-ready?

CRANE is in active development and used in real compliance engagements. Core modules are stable, but some advanced features are still evolving. It is not yet recommended for fully unattended production use without technical oversight — run it with someone who can keep an eye on updates and backups.

What does it cost?

Nothing. CRANE is free and open source under AGPL-3.0. There are no per-seat or per-client licensing fees — which is why consultants can run one instance per client at no marginal cost.

What does AGPL-3.0 mean for me?

You can use, audit, fork and extend CRANE freely. The key obligation of the AGPL is that if you modify CRANE and offer it to others over a network, you must make your modified source available to those users under the same licence. For internal self-hosted use, you simply run it.

Where does my data go?

Nowhere you don't control. All data stays in your own PostgreSQL instance, with no telemetry, no callbacks and no external dependencies at runtime. You can export your full dataset at any time.

Which SBOM format does CRANE accept?

CycloneDX. CRANE scores SBOM quality, validates CRA requirements and checks NTIA minimum elements, and can diff two SBOM versions.

Do I have to run Trivy?

No. Trivy is optional. CRANE uses OSV and NVD data with EPSS scoring out of the box; Trivy adds deeper scanning if you enable it.

Installation & first run

The first start is taking several minutes — is it stuck?

Almost certainly not. The first run takes 3–5 minutes while Docker builds the backend image and downloads the vulnerability database. Watch progress with:

docker compose logs -f

A port is already in use

If something else is already bound to 5173 or 8000, edit the host ports in your .env and restart. Check what's using a port with:

lsof -i :5173        # macOS / Linux
netstat -ano | findstr :5173   # Windows

Windows: containers fail to start

Make sure Docker Desktop is set to Linux containers — right-click the Docker tray icon and switch if needed. CRANE's images are Linux-based.

I can't log in / forgot the admin password

The default credentials are admin@example.com / admin1234, and you're prompted to change the password on first login. If you've lost access, you can reset the relevant record directly in the database or recreate the stack from a backup. Never leave the default password in place on a reachable instance.

How do I update to a newer version?

git pull
docker compose up -d --build

Database migrations are handled by Alembic on startup. Back up first — see Backups.

How do I completely reset my instance?

This deletes all data

docker compose down -v removes the volumes, including your PostgreSQL database. Export or back up first if you need the data.

Using the platform

How should consultants isolate client data?

Run one instance per client, each in its own directory with its own .env and database volume. See Running multiple isolated instances.

Can I integrate CRANE with my CI or issue tracker?

You can drive everything through the REST API today. Native GitHub / GitLab and Jira / GitHub Issues integrations are on the roadmap.
