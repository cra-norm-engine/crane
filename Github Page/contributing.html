Contributing & Roadmap

CRANE is open source and built in the open. Whether you're filing a bug, improving the docs, or shipping a feature, here's how to get involved — and where the project is heading.

How to contribute

  1. Open an issue first

    For anything beyond a trivial fix, open an issue to discuss it before writing code. This avoids wasted effort and keeps direction aligned.

  2. Fork & branch

    Work on a feature branch in your fork. Keep changes focused — one concern per pull request.

  3. Follow the contributing guide

    Read CONTRIBUTING.md for setup, conventions and expectations.

  4. Open a pull request

    Describe what changed and why, and link the issue it resolves.

Please open an issue before submitting a PR for significant changes.

Development setup

The repository is a Docker-first monorepo with a backend (FastAPI / Python 3.12) and a frontend (Vue 3 / TypeScript). The quickest way to a working dev environment is the manual install:

Terminal
git clone https://github.com/cra-norm-engine/crane.git
cd crane
cp .env.example .env   # set BACKEND_SECRET_KEY + POSTGRES_PASSWORD
docker compose up -d --build

See Configuration & Deployment for the full environment reference.

Roadmap

Priorities, grouped by horizon. The headline near-term goal is full support for CRA reporting obligations ahead of the September 2026 deadline.

Near term

  • Full compliance with CRA reporting obligations before 11 September 2026.
  • Email notifications (end-of-support alerts, gate approvals).
  • GitHub / GitLab integration.

Medium term

  • Integration of CENELEC vertical and horizontal standards.
  • Jira / GitHub Issues integration.
  • Multi-tenant support.

Long term

  • Formalised conformity reasoning.
  • AI integration.
  • Optimisation and performance.

Want to influence the roadmap? The most useful thing you can do is describe your real CRA compliance workflow in a GitHub issue — concrete needs shape priorities.
