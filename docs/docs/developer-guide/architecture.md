# Architecture

CRA Conformity Management is a self-hosted, three-tier web application composed of a Vue 3 frontend, a FastAPI backend, and a PostgreSQL database. All three services are orchestrated via Docker Compose.

## Technology Stack

| Layer | Technology | Version |
|---|---|---|
| Frontend | Vue 3 + TypeScript | Vue 3.5 |
| State management | Pinia | 2.x |
| HTTP client | Axios | 1.x |
| Backend | FastAPI | 0.115 |
| ORM | SQLAlchemy | 2.x |
| Schema validation | Pydantic | v2 |
| Database migrations | Alembic | 1.x |
| Database | PostgreSQL | 16 |
| Authentication | JWT (python-jose) | — |
| LDAP | ldap3 | — |
| Container runtime | Docker + Docker Compose | 24+ / 2.20+ |

## Backend Architecture

The backend follows a layered architecture:

```
Router (FastAPI) → Service → Repository → ORM Model → Database
```

- **Routers** handle HTTP request parsing, authentication, and response serialisation using Pydantic schemas
- **Services** contain all business logic and orchestrate across repositories
- **Repositories** encapsulate all database queries using SQLAlchemy 2.x `select()` statements
- **Models** define the database schema using SQLAlchemy declarative mapping with `Mapped` type annotations

### Key Design Decisions

- **UUID primary keys** on all tables, generated by the database
- **Immutable audit log** — audit events are append-only; the service layer calls `create_audit_event()` for all state-changing operations
- **Eager loading** — repositories use `selectinload()` to avoid N+1 query problems on all list endpoints
- **No lazy loading** — SQLAlchemy lazy loading is not used; all relationships are loaded explicitly in the repository layer

## Frontend Architecture

The frontend is a single-page application built with Vue 3 Composition API and `<script setup>`. Each compliance workflow corresponds to a view component under `src/views/`.

- **Axios services** (`src/services/`) abstract all API calls and handle authentication headers
- **Pinia stores** manage authentication state and user session
- **Vue Router** handles navigation with route-level permission guards
- **TypeScript interfaces** in `src/types/` mirror the backend Pydantic schemas

## Authentication

JWT-based authentication with short-lived access tokens. The backend issues tokens on login; the frontend stores the token in memory (not localStorage) and includes it in the `Authorization: Bearer` header on all API requests.

LDAP authentication is handled server-side: the backend authenticates against the LDAP directory and issues a JWT on success. LDAP credentials are never passed to the frontend.

## Audit Log

All state-changing operations write an immutable audit event to the `audit_events` table. Audit events record the actor, the action, the affected entity, and a JSON payload with before/after state. The audit log cannot be modified or deleted by any application-level operation.
