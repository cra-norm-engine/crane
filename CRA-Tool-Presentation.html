The Challenge

CRA compliance is complex

📋
Scope Assessment
Determining whether a product falls under the CRA — and which class — requires evaluating multiple criteria against Article 3 definitions.
🔍
SBOM Obligations
Article 13 mandates a machine-readable Software Bill of Materials. Maintaining accuracy across releases with multi-scanner CVE coverage is resource-intensive.
⏱️
Incident Timelines
Article 14 requires actively exploited vulnerability notifications to ENISA within 24 hours — with a full report within 72 hours.
🗂️
Audit Evidence
Conformity assessment bodies expect traceable, timestamped documentation covering the entire product lifecycle — not spreadsheets.
🔗
Supply Chain Visibility
Identifying transitive dependencies with known vulnerabilities across multiple product releases demands automated, version-aware tooling.
Platform Capabilities

Everything compliance in one place

🛡️
Scope Wizard
Guided assessment against CRA Article 3 criteria. Instantly determines in-scope / out-of-scope, classification (Default / Class I / Class II), and recommended conformity route.
Art. 3 Classification Conformity route
📦
SBOM Analyser
Uploads SBOMs and runs multi-scanner analysis (OSV, Trivy, NVD). Scores quality against NTIA minimum fields and CRA Phase 2 standards. Differential diff between releases.
Art. 13 NTIA CVE
🚨
Vulnerability Handling
Full CVD workflow with severity tracking, coordinated disclosure timelines, and automatic lifecycle notifications to registered stakeholders.
Art. 13–14 CVD PSIRT
📡
ENISA Reporting
Structured incident reporting to ENISA per Art. 14. Tracks 24-hour early warning and 72-hour notification deadlines with auto-generated report drafts.
Art. 14 ENISA
📜
Certification Records
Manage EU DoC and EU DoCA declarations of conformity per Annex IV. Attaches evidence artefacts and links to specific product releases.
Annex IV DoC DoCA
🕵️
Audit Trail
Immutable, timestamped event log for every action across products, releases, SBOMs, vulnerabilities, and certifications. Export-ready for assessors.
Annex I Traceability
Deployment & Integration

Built for enterprise environments

1
Self-hosted Docker deployment
Single docker-compose up brings up the API, Vue 3 frontend, and PostgreSQL. Air-gapped or cloud-hosted — you control the data.
2
LDAP / Active Directory integration
Connects to existing corporate directories for SSO. Role-based access control (Admin, Auditor, Developer, Viewer) maps to your org structure.
3
REST API + webhook events
Every action is available via a versioned REST API. Integrate with your existing CI/CD pipelines, ITSM, or GRC platform.
4
Open source core (AGPL v3)
The CRANE core is publicly available at github.com/cra-norm-engine/crane. No vendor lock-in. Extend or audit the codebase freely. Modifications deployed as a network service must remain open source.

Getting started

🗺️
1 — Scoping Workshop
Half-day session to inventory your product portfolio, identify CRA-applicable items, and classify them using the built-in scope wizard. Output: a prioritised compliance roadmap.
🚀
2 — Pilot Deployment
Deploy CRANE in your environment (on-prem or cloud), onboard 1–2 pilot products, ingest existing SBOMs, and wire up your CVD process. Target: 2 weeks.
✅
3 — Full Roll-out
Expand to the full product portfolio, enable LDAP SSO, connect CI/CD pipelines for automated SBOM ingestion, and produce the first audit-ready evidence package.

What you can — and can't — do

✅ Permitted — no approval needed
🏢 Internal use — deploy and run CRANE inside your organisation for any purpose
🖥️ Host unmodified for clients — run CRANE as a hosted service without touching the source code
⚙️ Configuration & infrastructure changes — env vars, Docker setup, reverse proxy, custom domains
💼 Sell services around it — consulting, deployment, training, compliance advisory
🔬 Modify for internal use — customise freely as long as the modified version is not offered to external users over a network
⛔ Requires permission from the project owner
🔒 Closed-source modifications hosted publicly — deploying a modified version as a network service without releasing the changed source Request permission
☁️ Proprietary SaaS product — building a commercial cloud platform on top of CRANE with proprietary modifications Request permission
📦 Re-licensing or sublicensing — distributing CRANE or a derivative under a different or more restrictive license Request permission
